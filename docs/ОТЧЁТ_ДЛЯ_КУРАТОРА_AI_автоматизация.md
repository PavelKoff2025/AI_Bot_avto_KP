# Отчёт о выполненной работе  
## Тема урока: «AI-автоматизация»

**Проект:** AI Bot — автогенерация коммерческих предложений (КП)  
**Репозиторий:** https://github.com/PavelKoff2025/AI_Bot_avto_KP  
**Контекст:** автоматизация подготовки документов отдела продаж строительной компании «Дом-Мастер» на основе транскрибации клиентского звонка и технологий ИИ  
**Дата:** август 2026  

---

## 1. Цель работы

Изучить и применить на практике цепочку **AI-автоматизации документов**:

> транскрибация диалога → анализ LLM (структурированный JSON) → HTML-шаблон (Jinja2) → PDF (WeasyPrint) → доставка менеджеру (Telegram)

Практически — сократить ручную работу менеджера ОП после звонка: вместо ручной сборки сметы и КП бот за минуты выдаёт готовый пакет PDF.

---

## 2. Краткий итог

Реализован полноценный Python-проект с двумя точками входа:

| Точка входа | Назначение |
|---|---|
| `main.py` + `flask_app.py` | CLI / учебный пайплайн отчётов (клиентский, design, АР, ИР, КП) |
| `bot.py` | Telegram-бот для менеджера: диалог → проверка данных → КП → АР/ИР → PDF / ZIP |

Стек урока соблюдён и расширен под ДЗ: **OpenAI, Jinja2, WeasyPrint, python-dotenv, Flask**, плюс **aiogram 3** и **pypdf**.

## 3. Этапы выполнения (хронология работ)

### Этап A. Базовый генератор отчётов (по ТЗ урока)

1. Создана структура проекта: `main.py`, `templates/`, `reports/`, `utils/`, `.env`, `requirements.txt`.
2. Реализован пайплайн:
   - чтение транскрибации (файл или stdin);
   - запрос к OpenAI с системным промптом;
   - разбор ответа в JSON;
   - рендер HTML через Jinja2;
   - конвертация в PDF через WeasyPrint.
3. В отчёт добавлены поля, важные для продаж: **желаемые сроки**, **стоимость/бюджет**, **пожелания к продукту**.
4. Настроены шрифты **DejaVu Sans** для корректной кириллицы в PDF.
5. PDF приведён к формату **A4** (как в демонстрации преподавателя), а не «бесконечная» HTML-лента.
6. Добавлен опциональный **Flask**-эндпоинт для локальной выдачи отчётов.

### Этап B. Предметная область «Дом-Мастер»

1. В качестве эталона использован **протокол телефонного разговора № 12/07** (`sample_dialog.txt`): менеджер Светлана / заказчик Иван, строительство ИЖС.
2. Расширены типы отчётов:
   - **client** — аналитика диалога;
   - **design** — бриф + AI-изображение (для сценария сайта/дизайна);
   - **АР** — архитектурный бриф + визуализация экстерьера + **план помещений** (AI);
   - **ИР** — инженерные системы: ВК, канализация, газовое отопление, тёплые полы, вентиляция + ориентировочная смета.

### Этап C. Коммерческие предложения (КП)

1. Три варианта тёплого контура:
   - **Базовый** — газобетон;
   - **Средний +** — газобетон усиленный;
   - **Средний (оптимальный)** — клееный брус.
2. Генерация **PDF + HTML** (HTML удобен для правок перед финальной печатью).
3. Опции CLI: `--kp`, `--with-fz` (фасад), `--with-engineering` (приложение ИР).
4. Сводный документ: смета по всем вариантам + объединение PDF (`pypdf`).

### Этап D. Telegram-бот для менеджера ОП

Реализован сценарий FSM (aiogram):

1. Менеджер присылает `.txt` или текст транскрибации.
2. LLM проверяет **достаточность данных** относительно эталона (`utils/sufficiency.py`).
3. Если данных мало — бот указывает пробелы и просит дополнить.
4. Выбор варианта КП → вопрос «нужен АР?» → «нужен ИР?».
5. Сборка пакета PDF.
6. Действия после генерации:
   - скачать файлы;
   - собрать всё в **один PDF** (3 КП + смета + АР/ИР);
   - **ZIP** финального комплекта;
   - e-mail — **заготовка (stub)** с подсказкой сначала сделать ZIP;
   - новый звонок / сброс сессии.

### Этап E. Качество и публикация

1. Логирование этапов в консоль и `logs/bot.log`.
2. Обработка ошибок: уведомление пользователя + глобальный `on_global_error`.
3. README, About, MIT License, `.gitignore`.
4. Папка `docs/screenshots/` со скриншотами работы бота.
5. Раздел «Возможное развитие бота» в README.
6. Публикация на GitHub: https://github.com/PavelKoff2025/AI_Bot_avto_KP

## 4. Архитектура решения

```text
Транскрибация (.txt / Telegram)
        │
        ▼
┌───────────────────┐
│  OpenAI (LLM)     │  sufficiency / extract JSON / промпты АР·ИР
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│  Jinja2 templates │  kp / ar / engineering / summary / report
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐     ┌──────────────┐
│  WeasyPrint PDF   │────▶│  pypdf merge │  (сводный документ)
└─────────┬─────────┘     └──────────────┘
          │
          ▼
   Telegram / reports/ / ZIP
```

**Ключевые модули `utils/`:**

| Модуль | Роль |
|---|---|
| `ai_processor.py` | промпты и вызовы OpenAI, разбор JSON |
| `pdf_generator.py` | HTML → PDF, шрифты, A4 |
| `report_service.py` | пайплайны отчётов client / design / AR |
| `image_generator.py` | генерация изображений (экстерьер, план) |
| `kp_generator.py` | варианты КП, ФЗ, цены тёплого контура |
| `engineering_generator.py` | пакет ИР и смета |
| `sufficiency.py` | проверка полноты транскрибации |
| `package_builder.py` | сборка пакета для бота |
| `combined_document.py` | сводная смета + merge PDF |
| `logging_setup.py` | единое логирование |

## 7. Как воспроизвести результат

```bash
git clone https://github.com/PavelKoff2025/AI_Bot_avto_KP.git
cd AI_Bot_avto_KP
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # указать OPENAI_API_KEY и TELEGRAM_BOT_TOKEN

# CLI-отчёт / КП
python main.py sample_dialog.txt --type ar
python main.py --kp

# Telegram-бот
python bot.py
```

Логи работы бота: `logs/bot.log`.

## 8. Чему научился / что показал проект по теме «AI-автоматизация»

1. **Промпт-инжиниринг** под строгий JSON-выход и разные роли (аналитик, архитектор, инженер, проверка completeness).
2. **Разделение LLM и рендера:** модель даёт данные, шаблоны и типографика отвечают за «печатный» вид.
3. **Продуктовый контур:** не только «сгенерировать текст», а довести документ до менеджера в привычном канале (Telegram) с выбором вариантов.
4. **Ограничения прототипа:** без живых прайсов из БД цены ориентировочные; e-mail и CRM — следующий слой интеграции.
5. **Наблюдаемость:** логи этапов нужны, когда генерация PDF или вызов API падает в середине сценария.
